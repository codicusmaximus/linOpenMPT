# mfc-qt

MFC and the Win32 API on Qt 6, so that an MFC application builds and runs
natively on Linux with its own code unchanged.

mfc-qt does not wrap MFC in Qt or translate an application into Qt code.
Instead it rebuilds the stack MFC sits on, the way Windows does:

| Layer | Directory | What it is |
|-------|-----------|------------|
| Win32 on Qt | `src/qtwin/` | Every `HWND` is a `QWidget`. Qt's events become window messages, sent to window procedures. Also GDI on `QPainter`, the standard and common controls (edit, list box, combo box, list view, tree view, toolbar, tab, trackbar, ...), dialogs from templates, menus, accelerators, resources, the clipboard, drag and drop, touch gestures and accessibility. |
| MFC | `src/mfc/` | `CWnd` and message maps, `CDC` and the GDI objects, dialogs and DDX, `CWinApp` and its message loop, documents and views, frames, splitters, control bars and docking, property sheets. It is written against the Win32 API only, as MFC is on Windows. |
| Base | `src/win32/`, `include/` | The Windows and MFC headers (`<afxwin.h>`, `<afxcmn.h>`, `<tchar.h>`, ...), base types, `CString` and the collections, kernel32 (files, threads, time, INI files), winmm MIDI input. |
| Resources | `tools/`, `cmake/` | A resource compiler for `.rc` scripts as Visual Studio writes them, and `mfcqt_add_resources()` to link the result into a target. |

Window procedures, message maps, owner drawing, subclassing and dialog
templates all behave as they do on Windows. The application's own window
code runs unchanged. Controls take their look from the Qt style, so they
match the rest of the desktop.

mfc-qt started inside [linOpenMPT](https://github.com/codicusmaximus/linOpenMPT),
a native Linux port of the OpenMPT tracker. It runs all of OpenMPT's UI: about
110 source files and 79 dialogs. It covers what OpenMPT uses of MFC and
Win32, which is a large part of both, but not all of either. Another
application may need pieces added; see [docs/PORTING.md](docs/PORTING.md).

## Requirements

- Linux (X11 or Wayland), a C++20 compiler (GCC 12+ or Clang 15+), CMake 3.22+
- Qt 6.4+ (Core, Gui, Widgets; Test for the tests)
- Python 3.8+ (the resource compiler)
- Optional: RtMidi, for MIDI input (`midiIn...`); xcb, to embed other
  programs' X11 windows (for example plugin editors running in Wine)

## Using it

Add it to your project, for example as a git submodule, then:

```cmake
add_subdirectory(mfc-qt)

add_executable(myapp main.cpp MainFrm.cpp ...)
target_link_libraries(myapp PRIVATE mfcqt::mfcqt)
mfcqt_add_resources(myapp myapp.rc FUNCTION RegisterMyAppResources WINDOWS_PATHS)
```

Before the first window is created, create a `QApplication`, then call the
registration function:

```cpp
#include <afxwin.h>
#include <QtWidgets/QApplication>

void RegisterMyAppResources();  // generated by mfcqt_add_resources

int main(int argc, char **argv)
{
	QApplication qt(argc, argv);
	RegisterMyAppResources();
	// Your CWinApp object's InitInstance() and Run(), as WinMain would call them.
	...
}
```

[docs/PORTING.md](docs/PORTING.md) covers the rest: the entry point, what
differs from Windows, and what to do when something is missing.

## Building and testing it alone

```sh
cmake -S . -B build -G Ninja
cmake --build build
ctest --test-dir build
```

The tests run offscreen (`QT_QPA_PLATFORM=offscreen`). They check windows,
messages, painting, input, controls, message maps, CWnd, the message loop,
touch, accessibility, and a resource script of their own (`tests/resources.rc`).
